# Docstrings are tight, with math in inline TeX

A docstring states what a name and a signature cannot: a one-line summary, and a body only for a convention or a behaviour a caller can observe. It leaves out array shapes, implementation notes and conventions stated once in the module docstring, and an implementation of a protocol inherits the protocol explicitly and marks its methods `@override`, without a docstring of its own. Math is inline TeX between `$...$`, following the conventions of `NOTATION.md`, and appears only where a formula settles a convention, such as a normalization, a sign or an index order; prose uses words ("time step", not $\Delta t$). The first docstrings wrote formulas in Unicode, which drifted (`∂_yuₓ`, `v` for $\nu$) and has no subscript for every letter, and ASCII math would be a notation of its own; TeX is the notation of the field, and GitHub renders it in the notation, the glossary, the ADRs and the issues. Python sources are therefore ASCII only, as `scripts/check_source.py` checks in CI, and a docstring with a backslash is a raw string, as ruff's D301 requires, so that `\nu` and `\nabla` are not read as escapes.
